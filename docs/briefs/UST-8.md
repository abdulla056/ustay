# Worker Brief — UST-8: Database & Drizzle conventions

Linear: https://linear.app/abdulla-safar/issue/UST-8/database-and-drizzle-conventions

## Mission

Lock the schema conventions BEFORE modeling the domain (Phase 1), so every table is consistent.
Output is shared helpers + a short conventions doc — not domain tables.

## Read first (in the repo)

- `src/lib/server/db/` — `schema.ts` (app schema, currently just re-exports auth),
  `index.ts` (drizzle client), `auth.schema.ts` (GENERATED by better-auth — do not hand-edit)
- `drizzle.config.ts`, and the `db:*` scripts in `package.json`
- `CLAUDE.md` + project memory

## Scope (do)

- [ ] Decide + document the **ID strategy** (recommend UUID for public-facing entities; explain
      the trade-off vs serial). Provide a reusable column helper.
- [ ] A **timestamps** helper (`createdAt`, `updatedAt` with `$onUpdate`) reused by all tables.
- [ ] **Naming conventions** (snake_case columns, table naming — match the existing auth tables).
- [ ] **Slug strategy** for public URLs (properties, destinations).
- [ ] Put helpers in a module (e.g. `src/lib/server/db/helpers.ts`) and show them used by a tiny
      throwaway/example or documented usage (no real domain tables yet).
- [ ] Short doc `docs/DATABASE.md`: conventions + migration workflow (`db:generate` vs `db:push`).

## Out of scope (don't)

- Don't model domain entities (Property/Room/etc.) — that's Phase 1.
- Don't hand-edit `auth.schema.ts` (it's generated).
- Don't touch `package.json` deps (avoids conflicts with parallel UST-6/UST-9).

## Acceptance

- Reusable id + timestamps helpers exist; conventions + migration workflow documented.
- `bun run check` / `lint` / `test` all green. (DB need not be running; keep it type-level.)
